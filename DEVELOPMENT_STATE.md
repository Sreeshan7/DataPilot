## What the product does now

```
User A (needs a dataset)                     User B (has / names a dataset)
  POST /api/v1/datasets/recommend              POST /api/v1/datasets/analyze
  requirements -> discovery -> ranking         file | name | link  (+ optional target, project_goal)
  -> intelligence -> confidence                 -> parse or research registries
  -> final recommendation                       -> schema, stats, quality, targets, tasks
                                                -> project_intelligence (Phase 5)
            \                                  /
             POST /api/v1/assist  (unified: routes automatically, asks when unsure,
                                   offers A->B and B->A transitions)
             POST /api/v1/intent/resolve  (routing decision only)
```

Governing rule, enforced in code and tests: **if DataPilot has the data it analyses the data; if it
only has a name or link it researches trusted registries and reports only what they publish; if it
cannot verify something it says UNKNOWN; it never pretends.**

### Phase 5 behaviour worth knowing
- **Feature intelligence exists only with rows.** Association (Spearman / bias-corrected Cramer's V /
  correlation ratio), mutual information, and permutation importance of a held-out random forest
  (ROC AUC for binary, balanced accuracy for multiclass, R2 for regression/forecast), judged against
  3-10 random "yardstick" columns and a trivial baseline. A registry-only dataset gets no numbers
  (schema validators enforce it); its features are UNKNOWN (or IDENTIFIER where the registry says).
- Roles: RECOMMENDED_FEATURE (>= 2 of 3 measures agree) / USE_WITH_CAUTION / POSSIBLE_LEAKAGE (kept
  out of the model so it cannot hide others) / IDENTIFIER / LOW_SIGNAL / UNKNOWN. If the model does
  not beat a trivial predictor, per-feature importances are **withheld**, not shown with a caveat.
- Leakage is decided by one shared helper (`association.looks_like_leakage`) so quality findings and
  roles cannot disagree. A correlation ratio >= 0.98 alone is not leakage (separable classes);
  the one-column rule must also be near-perfect.
- Ideas (3-5 when supportable) are deterministic and grounded in real columns, re-validated before
  return. Gemini is optional (`use_ai`), one structured call, **prose only**, prompt carries no cell
  values and withholds identifier/sensitive column names, reply is validated per idea (unknown
  backticked column, accuracy promise, causal claim, link/markdown, length) and falls back with a
  warning. A failed/slow/unconfigured call never fails the analysis.
- Goal compatibility (MATCH/UNKNOWN/MISMATCH over target, task, features, volume) is a deterministic
  reading of the goal text. MISMATCH needs positive contradicting evidence; a named input absent
  from the data caps the answer at UNKNOWN; MISMATCH suggests `FIND_ALTERNATIVE_DATASET`.
  It does **not** reuse User A's requirement analyzer (that needs Gemini); it uses the project's
  concept dictionary for target matching.

## Schema discovery for datasets known only by name or link (added after user testing)

Problem found by the user: analysing a Kaggle dataset by link or name showed only blanks, because Kaggle publishes
no schema. Fixed with a ladder, each rung labelled as exactly what it is:

1. **Registry structured schema** (UCI, OpenML, HF card) = `registry_verified`.
2. **Hugging Face datasets-server** (`/info`) when the card lists no features = `registry_verified` (real feature
   types and row counts).
3. **The dataset file's own header** (Kaggle): `SafeFetcher.get_prefix` reads only the first 64 KB of the main
   csv/tsv (Kaggle redirects to `storage.googleapis.com`; that exact host only, https, default port, credential
   never forwarded, signed URL never logged, body abandoned at the cap even if Range is ignored). `peek.py`
   returns column names, kinds (Continuous/Integer/Binary/Categorical/Text, from <=300 sampled rows), unique-per-row
   identifier roles and a **row estimate from file size** (`row_count_evidence = inferred`, shown as "~N").
   No cell value leaves the module. Evidence level stays `registry_verified` with `schema_source` "file header
   (first N KB of X.csv, read from Kaggle)". Switch: `EXTERNAL_PEEK_ENABLED`.
4. **Last resort, web lookup** (`web_knowledge.py`): when no registry knows a name, or a record has no columns
   and no readable header: ONE cached Gemini + Google Search grounding call. Rejected unless real grounded
   source links come back; reply validated field by field; result is `ai_inferred` (columns, rows), carries
   `web_sources`, resolution is PROBABLE at <= 0.5 confidence with "confirm it" wording, never STRONG targets,
   never a compatibility MISMATCH. Quota/auth/timeout => "found nothing (reason)", never cached, never fatal.
   Switch: `WEB_LOOKUP_ENABLED`. **Not verified live** (the Gemini free quota was exhausted while building it; it is
   covered by 25 unit tests with a fake searcher).
- Target cues for schema-only datasets now include a typed last column and outcome-style names (score, price,
  status...), capped at POSSIBLE; typed columns give a task (regression for a many-valued numeric target).
- Live results: Kaggle "Student Performance Factors" by name or link -> 20 real columns, `exam_score` possible
  target, regression; "Exam Score Prediction Dataset" -> 13 columns; "Titanic" via OpenML; "Telco Customer Churn"
  via Hugging Face.

## Frontend (`datapilot/frontend`)

React 18 + TypeScript + Vite 5 + Tailwind 3 (Node 18 compatible), hand-written shadcn-style primitives, lucide
icons, self-hosted Inter/JetBrains Mono, `react-markdown` (no raw HTML). No router, no state library, no auth.

Run: backend `uvicorn app.main:app --port 8000`, then `cd datapilot/frontend && npm install && npm run dev`
(Vite proxies `/api`, `/ready`, `/health`; set `DATAPILOT_BACKEND=http://127.0.0.1:PORT` if the backend is not on
8000). Checks: `npm run typecheck`, `npm test` (33 unit tests), `npm run build`; browser flows against the real
backend: `node scripts/flow.mjs discovery|analyze|research [mobile]` and `node scripts/checks.mjs` (19 behavioural
checks; uses Edge through playwright-core, screenshots go to git-ignored `.shots/`).

- **Contracts:** `src/types/api.ts` is generated from the backend OpenAPI (`npm run gen:api`); `types/index.ts`
  aliases it (response types wrapped in `DeepRequired` because the backend always serialises defaults).
  `src/api/` is the only code that calls HTTP (typed `ApiError`, timeouts, AbortSignal, real upload progress via XHR).
- **Journey:** one composer; the user never picks a mode. Text -> `POST /intent/resolve` (free, deterministic, so
  "understood your request as ..." is a real completed step) -> `POST /assist`. A file goes straight to `/assist`.
  Backend `next_actions` drive the buttons (`UPLOAD_FILE`, `ANALYZE_*`, `FIND_ALTERNATIVE_DATASET`,
  `RESEARCH_PROBLEM`); research is a separate explicit card with an off-by-default "AI summary" tick (disabled
  when `/ready` says Gemini is not configured). The project described earlier in a conversation is passed as
  `project_goal` when a dataset is analysed later.
- **Activity honesty:** the backend returns one final answer, so there is no live stage feed and none is faked.
  While a request is open the UI ticks only what is known (understood, bytes uploaded with a real progress bar) and

  endpoint (e.g. SSE `/assist/stream` emitting stage events); that is the minimum backend change required.
- **Results:** dataset cards (rank, source, score, compatibility, matched/unknown/missing features, why, risks,

## Research mode (optional "Research this problem")

Flow, only when the user selects it: structured context -> 3-5 deterministic queries -> web search ->
normalise + dedupe -> explainable relevance ranking -> methods/metrics read from retrieved text ->
algorithm recommendations -> optionally ONE Gemini call. Code: `services/research/` (`queries`, `providers`,
`normalize`, `ranking`, `methods`, `recommend`, `synthesis`, `offer`, `service`), `schemas/research.py`,
`prompts/research.py`, `api/v1/research.py`, `LLMService.generate_research_synthesis`.

- **Provider seam:** `ResearchProvider` interface; only `WebSearchProvider` exists. It uses DuckDuckGo's
  keyless HTML endpoint through httpx (no paid API, no new dependency, never fetches result pages, no
  redirects, size/time caps). Semantic Scholar / OpenAlex / Crossref / arXiv providers are future work.
- **Honest degradation:** rate limited or unreadable search -> `search_unavailable`, no papers, no Gemini call.
  Zero academic matches -> `no_results`. Too little context -> `needs_clarification` (no search made).
- **Evidence labels:** `web_verified` (from a retrieved snippet/title), `source_metadata` (URL/site: arXiv id,
  DOI, venue), `ai_inferred` (Gemini only, kept in `ai_interpretation`, never merged into `methods`). Authors,
  citation counts stay `None`; a year is set only when the URL or text states it.
- **Dedup:** DOI, arXiv id, canonical URL, or an identical normalised title; similar titles stay separate.
  Only an allowlist of academic hosts (publishers, repositories, .edu/.ac.*) is kept.
- **Ranking (0-100, explainable, not a quality score):** problem 40, task/domain/target 10 each, method 10,
  recency 10 (unknown year earns nothing), source 10. No citation counts.
- **Metrics** are kept with paper, URL, and the sentence "reported by the source in its own setting".
- **Gemini budget:** 0 calls unless `options.use_ai`; then exactly 1 (the research method is deliberately NOT
  wrapped in the transient-retry decorator). Prompt = compact normalised evidence in a `<data>` block (snippets
  capped at 280 chars). Reply is rejected as a whole if it has links/DOIs, percentages no source reported,
  result promises, "we ran" claims, author attribution, unknown `[p:ID]` refs, or quoted names not retrieved;
  then DataPilot's own summary stands. Key is never in prompts, logs, tests or responses.
- **Offer, not run:** `NextAction` gained optional `id/label/available/reason`; `/analyze` and `/assist` add a
  `RESEARCH_PROBLEM` action with a pre-filled, valid `ResearchRequest` payload (available only when a problem
  can be stated). A test proves no search is made by `/assist`.
- **Live checks (2026-10-05):** web search returned 13 results / 8 distinct real academic papers (arXiv,
  IEEE, Springer, Nature, ScienceDirect, MDPI, ResearchGate) on the first full run; subsequent runs were
  rate limited by the keyless endpoint (status `search_unavailable`, handled as designed). Gemini synthesis
  was run live once over frozen evidence: 1 call, validated, grounded.
- **Limits:** the search page is not a documented API and can rate-limit or change markup; evidence is
  title+snippet only (full papers/PDFs are not opened), so most snippets name no method and methods/figures
  are "not found in the snippet", never "absent"; queries are quoted phrases that can narrow results; years
  from snippets can be a mention rather than a publication date (labelled `web_verified`).

## Known limitations

1. Everything above is measured on synthetic data written by the same author as the rules.
2. Routing is regexes: ~65% of unseen phrasings resolve; the rest ask (never mis-route in measurement).
3. Registry-only datasets: no rows are read, so no statistics, quality, balance or importance, by design.
   Kaggle publishes no schema (0/20 probed): UNKNOWN. HF publishes columns for ~1 in 5 datasets.
4. Importance is conservative on weak signal (small samples, imbalanced classes): real but weak drivers
   (e.g. `overtime` in the attrition set) can land as LOW_SIGNAL / USE_WITH_CAUTION. Forecasting
   importance uses a chronological split with no lag features; a trending target makes the forest
   unreliable and importances are withheld.
5. A tree model cannot extrapolate a trend; text columns are not assessed (only listed/ideated).
6. Goal compatibility reads text with regexes plus a small abbreviation table and the concept
   dictionary; unusual synonyms stay UNKNOWN.
7. Defaults put a 5,000-row / 100-tree cap on importance; a very wide file models only its 40 most
   associated columns and says so.
8. Phase 1 gaps carried over (dictionary `dataset_requirements` not merged; `conflicts` always empty;
   `llm_request_timeout`/`llm_max_retries` unused by `generate_content`); Postman collection covers only Phase 1.
9. User A limitations 1-12 from the Phase 3 handoff still stand (Kaggle metadata is thin; ranking benchmark
   is authored; 2 intentional golden failures in `golden_set.KNOWN_FAILURES`).

## Analysing a registry dataset from the internet, robustly (2026-10-05)
- **Root causes found on a real Kaggle dataset:** (1) Kaggle serves each file as a ZIP, so the header reader was parsing
  compressed bytes ("no recognisable header row"); (2) Google Search grounding has no usable quota on any model for this
  key (429 on every model, both keys), so the "web lookup" never worked.
- **Fixes:** `peek.unpack_prefix` decodes the START of a zip (stored/deflate, zip64 sizes) or gzip stream, output bounded
  to 1 MB; the real uncompressed size gives the row estimate. New `external/page_reader.py`: DataPilot searches the web,
  fetches a few public pages itself (https, public hosts only, redirects re-checked, size capped), and one plain Gemini
  call extracts column names; software then accepts a column ONLY if its name is written on a fetched page, a row count
  only if the number is written, sources are the fetched pages (never model URLs), >= 3 verified columns required.
  Result stays `AI_INFERRED` with cited pages. Order: registry structure -> file header -> description -> page reader ->
  grounded search (paused for 30 min after two quota refusals in a row).
- **Also found:** `search_grounded`/analysis Gemini calls blocked the event loop (fixed earlier today).
- **Live checks:** Madrid real estate (Kaggle URL and name only) -> 58 columns, ~22.6k rows, target buy_price; Heart Failure and
  Spotify tracks via Hugging Face; Red Wine via Kaggle header; the page reader alone found verified columns for Palmer
  Penguins, Seoul Bike Sharing and Wisconsin Breast Cancer with cited pages.
- Limits: a header read gives names and rough kinds only (no missingness/importance); the page reader depends on the keyless
  search engine and on pages that actually list columns.
