## What the product does now

```
User A (needs a dataset)                     User B (has / names a dataset)
  POST /api/v1/datasets/recommend              POST /api/v1/datasets/analyze
  requirements -> discovery -> ranking         file | name | link  (+ optional target, project_goal)
  -> intelligence -> confidence                 -> parse or research registries
  -> final recommendation                       -> schema, stats, quality, targets, tasks
                                                -> project_intelligence (Phase 5)
            \                                  /
             POST /api/v1/assist  (unified: routes automatically, asks when unsure,
                                   offers A->B and B->A transitions)
             POST /api/v1/intent/resolve  (routing decision only)
```

Governing rule, enforced in code and tests: **if DataPilot has the data it analyses the data; if it
only has a name or link it researches trusted registries and reports only what they publish; if it
cannot verify something it says UNKNOWN; it never pretends.**

### Phase 5 behaviour worth knowing
- **Feature intelligence exists only with rows.** Association (Spearman / bias-corrected Cramer's V /
  correlation ratio), mutual information, and permutation importance of a held-out random forest
  (ROC AUC for binary, balanced accuracy for multiclass, R2 for regression/forecast), judged against
  3-10 random "yardstick" columns and a trivial baseline. A registry-only dataset gets no numbers
  (schema validators enforce it); its features are UNKNOWN (or IDENTIFIER where the registry says).
- Roles: RECOMMENDED_FEATURE (>= 2 of 3 measures agree) / USE_WITH_CAUTION / POSSIBLE_LEAKAGE (kept
  out of the model so it cannot hide others) / IDENTIFIER / LOW_SIGNAL / UNKNOWN. If the model does
  not beat a trivial predictor, per-feature importances are **withheld**, not shown with a caveat.
- Leakage is decided by one shared helper (`association.looks_like_leakage`) so quality findings and
  roles cannot disagree. A correlation ratio >= 0.98 alone is not leakage (separable classes);
  the one-column rule must also be near-perfect.
- Ideas (3-5 when supportable) are deterministic and grounded in real columns, re-validated before
  return. Gemini is optional (`use_ai`), one structured call, **prose only**, prompt carries no cell
  values and withholds identifier/sensitive column names, reply is validated per idea (unknown
  backticked column, accuracy promise, causal claim, link/markdown, length) and falls back with a
  warning. A failed/slow/unconfigured call never fails the analysis.
- Goal compatibility (MATCH/UNKNOWN/MISMATCH over target, task, features, volume) is a deterministic
  reading of the goal text. MISMATCH needs positive contradicting evidence; a named input absent
  from the data caps the answer at UNKNOWN; MISMATCH suggests `FIND_ALTERNATIVE_DATASET`.
  It does **not** reuse User A's requirement analyzer (that needs Gemini); it uses the project's
  concept dictionary for target matching.

## Known limitations

1. Everything above is measured on synthetic data written by the same author as the rules.
2. Routing is regexes: ~65% of unseen phrasings resolve; the rest ask (never mis-route in measurement).
3. Registry-only datasets: no rows are read, so no statistics, quality, balance or importance, by design.
   Kaggle publishes no schema (0/20 probed): UNKNOWN. HF publishes columns for ~1 in 5 datasets.
4. Importance is conservative on weak signal (small samples, imbalanced classes): real but weak drivers
   (e.g. `overtime` in the attrition set) can land as LOW_SIGNAL / USE_WITH_CAUTION. Forecasting
   importance uses a chronological split with no lag features; a trending target makes the forest
   unreliable and importances are withheld.
5. A tree model cannot extrapolate a trend; text columns are not assessed (only listed/ideated).
6. Goal compatibility reads text with regexes plus a small abbreviation table and the concept
   dictionary; unusual synonyms stay UNKNOWN.
7. Defaults put a 5,000-row / 100-tree cap on importance; a very wide file models only its 40 most
   associated columns and says so.
8. Phase 1 gaps carried over (dictionary `dataset_requirements` not merged; `conflicts` always empty;
   `llm_request_timeout`/`llm_max_retries` unused by `generate_content`); Postman collection covers only Phase 1.
9. User A limitations 1-12 from the Phase 3 handoff still stand (Kaggle metadata is thin; ranking benchmark
   is authored; 2 intentional golden failures in `golden_set.KNOWN_FAILURES`).

never appears in a prompt or result). Uploaded files are never executed or retained; messages and cell values

redirects re-validated, size/time caps); credentials go only to their own host.
